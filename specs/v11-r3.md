# Story S-V11-R3: Daily as React — briefing + loop + music (Sprint 3 re-draft)

Outcome: the React island opens the day (morning briefing: news,
weather, next steps) and music is contextual (iframe embed first,
suggestions otherwise). Zero API keys: all keyless fetches run in the
Python backend (backend adapters), the browser only renders. Calendar
is honest-scoped: no browser calendar API exists — day items come from
the paired-device bridge or manual entry until the native card lands.

  Daily view renders with stamped cache. Fail-fast lesson ports over:
  one dead source softens to null, never wipes live rows (eager + null
  filter, same as the proven Flutter _soft). Offline shows cached +
  age-stamped, never fake-fresh.

Acceptance:
- [ ] briefing renders with zero keys configured
- [ ] one dead source keeps the other four live (4/5 test ports over)
- [ ] offline shows cached briefing stamped with its age
Verification: fresh run with empty key store; airplane stale-stamp proof; dead-source unit test
Dependencies: bridge adapter endpoints (new island/*_adapter.py)
Files likely touched: island/briefing_adapter.py, island-ui/src/components/Daily.tsx, Daily tests
